# 5.2 Frequently Asked Questions

## Installation Issues

### Windows: App Doesn't Launch After Installation

**Possible causes**:
- Missing WebView2 runtime
- Antivirus software blocking

**Solutions**:
1. Install [Microsoft Edge WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)
2. Add CC Switch to your antivirus software's whitelist

### "Cannot Access Windows Credential Manager"

CC Switch stores keys in Windows Credential Manager; when it cannot reach it, it fails outright rather than falling back to plain-text storage.

**Solutions**:
1. Make sure the "Credential Manager" control panel opens normally
2. Make sure the Credential Manager related system service is running
3. In an enterprise domain environment where credentials are restricted from roaming with the profile, switch to local persistence
4. Click "Retry" in the dialog afterwards — the dialog offers no "Skip" option

## Provider Issues

### Provider Switch Doesn't Take Effect

**Cause**: CC Switch delivers credentials through **user environment variables**, while running terminal processes still hold the old values.

**Solutions**:
- Close and reopen the terminal (applies to Claude Code / Codex / Pi alike)
- Or click "Open Terminal" on the provider card in the Claude tab — the credentials are injected straight into that terminal
- If it still doesn't work after reopening the terminal, check whether `~/.claude/settings.local.json` or a project-level `.claude/settings.json` defines `env.ANTHROPIC_*` — those override the process environment variables. See [5.4 Environment Variable Conflicts](./5.4-env-conflict.md)

### Switch Refused, Asking for a Key

**Cause**: The provider never had an API Key saved, or it arrived via sync / import from another device.

**Solutions**: Edit the provider, re-enter the API Key (and the endpoint URL) and save.

> 💡 Keys are excluded from exports and sync, so after moving to another device you must fill them in again — that is by design, not a bug.

### Environment Variable Conflict Detected

**Cause**: A variable of the same name already exists in the user environment, was not written by CC Switch, and holds a different value.

**Solutions**: Choose "Take over (overwrite)" in the conflict dialog and run the switch again, or cancel the switch and handle it yourself. Note that taking over replaces the original value with no backup kept. See [5.4 Environment Variable Conflicts](./5.4-env-conflict.md).

### API Key Invalid

**Troubleshooting steps**:
1. Confirm the API Key is copied correctly (no extra spaces)
2. Confirm the API Key hasn't expired
3. Confirm the endpoint URL is correct
4. Confirm you reopened the terminal so the CLI reads the new variables

### How to Restore Official Login

**Steps**:
1. Select the "Official Login" preset (Claude / Codex)
2. Click "Enable"
3. Reopen the terminal
4. Follow the CLI tool's own login flow (e.g. `codex login`)

> 💡 CC Switch no longer handles OAuth login and does not overwrite your own sign-in state in `~/.codex/auth.json`.

## Data Issues

### Configuration Lost

**Possible causes**:
- Configuration directory was deleted
- Database corruption

**Solutions**:
1. Check if the `~/.cc-switch/` directory exists
2. Restore from backup: `~/.cc-switch/backups/`
3. Or import from a previously exported configuration file

> ⚠️ Losing the database does not affect the keys in Credential Manager, but the providers must be added again and their keys filled in. You can also inspect the leftover entries manually in the "Credential Manager" control panel by the `cc-switch/` prefix.

### Import Configuration Failed

**Possible causes**:
- Incorrect file format
- Version incompatibility

**Solutions**:
1. Confirm the file is an SQL backup exported by CC Switch
2. Check if the file content is complete
3. Try opening with a text editor to check format

### Export Refused, Possible Key Detected

Before exporting, CC Switch scans the text as a regression safeguard. A hit means abnormal data slipped into the database.

**Solutions**: Remove the suspicious provider and retry; when the plain text came from an import of an older export, the import flow extracts it into Credential Manager, so restart the app and export again.

## Other Issues

### Tray Icon Not Showing

**Windows**:
- Check taskbar settings to ensure the CC Switch icon is not hidden
- Check whether showing the tray icon is enabled under "Settings > General > Window Behavior"

### UI Display Issues

**Solutions**:
1. Try switching themes (light/dark)
2. Restart the app
3. Delete `~/.cc-switch/settings.json` to reset settings

### How to Upgrade to a New Version

CC Switch has no in-app update feature: it does not check for new versions on startup and never prompts you to download one.

**How to upgrade**: Download the latest Windows installer (MSI) or portable archive (ZIP) from [GitHub Releases](https://github.com/farion1231/cc-switch/releases) and install over the current version. Your configuration and credentials are unaffected.

## Lightweight Mode

### How to Enter Lightweight Mode?

Toggle "Lightweight Mode" from the system tray menu. The main window closes, and CC Switch runs as a tray-only app. Toggle again or click "Open main window" to exit.

### App Uses Less Memory in Lightweight Mode?

Yes. Lightweight Mode destroys the main window and its web view, reducing memory usage significantly while keeping tray menu functionality available.

## Getting Help

### Submit an Issue

If none of the above solutions work:

1. Visit [GitHub Issues](https://github.com/farion1231/cc-switch/issues)
2. Search for similar issues
3. If none found, create a new Issue
4. Provide the following information:
   - Windows version
   - CC Switch version
   - Problem description and reproduction steps
   - Error messages (if any)

### Log Files

CC Switch stores logs under its application configuration directory. By default this is `.cc-switch` in your home directory; if you changed the configuration directory in Advanced Settings, use that custom location instead.

When submitting an Issue, attach the files relevant to the problem:

- General and network errors: `cc-switch.log` in `~/.cc-switch/logs/` and its rotated files
- Application crashes: `~/.cc-switch/crash.log` plus `crash.log.1`, `crash.log.2`
- The default Windows location is `C:\Users\<username>\.cc-switch\...`

The runtime log rotates at 20 MB and retains the four most recent archives. Restarting the application does not clear existing logs. Logs never contain secret values, but they may include runtime environment details, so review them before posting publicly.

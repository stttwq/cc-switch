# 5.4 Environment Variable Conflicts

## Overview

CC Switch delivers credentials to the CLIs through **user environment variables** (registry `HKCU\Environment`). Because delivery relies on environment variables, a variable of the same name that you set elsewhere can conflict with it, so CC Switch detects and reports these conflicts.

**Variable prefixes that are detected**:

| Application | Matching Prefix |
|-------------|-----------------|
| Claude | `ANTHROPIC*` (e.g. `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`) |
| Codex | `OPENAI*` (e.g. `OPENAI_API_KEY`) |

CC Switch also records internally **which variables it wrote itself** (the `managed_env_vars` key of the `settings` table). Overwriting one of its own variables does not count as a conflict.

## Two Conflict Scenarios

### Blocking Conflict on Switch

When switching providers, if a variable about to be written already exists, was not written by CC Switch, and holds a different value — CC Switch does **not** write it and opens a conflict dialog.

| Field | Description |
|-------|-------------|
| Variable Name | Environment variable name |
| Current Value | Shows **only the last 4 characters** (e.g. `***wxyz`); the full value is never sent back to the UI |
| Ownership | `foreign` (an external variable) |

You can choose:

- **Take over (overwrite)**: CC Switch replaces the value with the new one, registers the variable as its own, and then completes the switch
- **Cancel the switch**: nothing is changed at all

> ⚠️ **Important**: After taking over, the original value is overwritten **and not kept** — CC Switch no longer backs up the value it replaces. Make sure you do not need the old value before taking over.

### Persistent Warning Banner

A yellow warning banner may appear at the top of the main interface listing the same-name variables it detected. Besides registry sources, it also includes a class of **read-only** warnings:

| Source | Description | Can CC Switch remove it |
|--------|-------------|-------------------------|
| User registry (`HKEY_CURRENT_USER\Environment`) | Windows user-level environment variable | ✅ Yes |
| System registry (`HKEY_LOCAL_MACHINE\...\Environment`) | Windows system-level environment variable | ❌ Reported read-only |
| `~/.claude/settings.local.json` | `env.ANTHROPIC_*` in Claude's own local override file | ❌ Reported read-only |

> 💡 User-level variables override system-level ones of the same name (except `PATH`), so a system-level variable of the same name usually only matters in scenarios where you do not use CC Switch.

## Resolve Conflicts

### Select Variables to Handle

1. Check the variables you want to handle (read-only sources cannot be checked)
2. Or click "Select All"

### Remove Variables

1. Click the "Remove Selected" button
2. Confirm the removal operation
3. CC Switch deletes the variable from `HKCU\Environment`, updates this process's environment accordingly, and broadcasts `WM_SETTINGCHANGE`

> ⚠️ **No more automatic backup**: earlier versions backed up variable values to a plain-text file before removal; that mechanism has been removed (the plain-text backup was itself part of what needed fixing). Confirm on your own that you do not need the original value before deleting.

## Dismiss Warning

If you confirm the conflict does not affect usage, you can:

1. Click the "Dismiss" button on the right side of the warning banner
2. The warning will be temporarily hidden
3. Detection will run again on next launch

## Manual Resolution

If you prefer not to use CC Switch to handle variables, you can do it manually:

### Windows user-level variables

1. Open "System Properties > Advanced > Environment Variables", or use PowerShell
2. Find the conflicting variable under **User variables**
3. Delete or modify the variable

### System-level variables

These require administrator privileges, and CC Switch never touches `HKLM`. Handle them yourself in the system variables section of the Environment Variables dialog.

### Claude's local override files

The `env.ANTHROPIC_*` entries in `~/.claude/settings.local.json` and in project-level `.claude/settings.json` take precedence over process environment variables and override the values delivered by CC Switch. CC Switch does not modify these files; delete or comment out the entries yourself.

## Why Do Conflicts Occur

The CLI reads environment variable values when the process starts, which may cause:

- Provider configurations set by CC Switch being overridden by external values
- API requests being sent to the wrong endpoint
- Using the wrong API key

## Best Practices

1. **Let CC Switch own these variables**: do not set `ANTHROPIC_*` / `OPENAI_API_KEY` separately in system environment variables or shell configuration
2. **Check regularly**: pay attention to conflict warnings and address them promptly
3. **Confirm the old value before taking over**: overwritten values are no longer held by CC Switch
4. **Reopen the terminal after changes**: CC Switch broadcasts `WM_SETTINGCHANGE`, but only newly started processes read it

## Undo a Takeover

If you took over a variable you actually wanted to keep:

1. Edit and switch to a different provider, or delete that provider — CC Switch removes the variables registered under its name
2. Clean up any leftover credential entries under "Settings > Advanced > Credential Manager Maintenance"
3. The original value is yours to restore (from your own backup, or by retrieving it again from the provider's console)

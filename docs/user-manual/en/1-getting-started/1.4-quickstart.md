# 1.4 Quick Start

This section helps you complete the initial setup in 5 minutes.

## Step 1: Add a Provider

1. Click the **+** button in the top-right corner of the main interface
2. Select your provider from the "Preset" dropdown
   - Common presets: Zhipu GLM, MiniMax, DeepSeek, Kimi, PackyCode
   - Or select "Custom" for manual configuration
3. Enter your **API Key**
4. Click "Add"

![image-20260108002807657](../../assets/image-20260108002807657.png)

> **Tip**: Presets auto-fill the endpoint URL, so you only need to enter your API Key. The key is written into Windows Credential Manager and is never stored in the database or in a configuration file.

## Step 2: Switch Provider

After adding, the provider appears in the list.

**Option 1: Switch from the main interface**
- Click the "Enable" button on the provider card

**Option 2: Quick switch via system tray**
- Right-click the CC Switch icon in the system tray
- Click the provider name directly

> ⚠️ **Note**: Switching delivers credentials by writing user environment variables (`HKCU\Environment`), so **terminals that are already open cannot see the new values and must be reopened**. To use them right away, click "Open Terminal" on the provider card — CC Switch injects the variables straight into that terminal process, no reopen needed.

## Step 3: Activation

After switching providers, each CLI tool activates differently:

| Application | Activation Method |
|-------------|-------------------|
| Claude Code | Requires reopening the terminal (only then are the new environment variables read) |
| Codex | Requires reopening the terminal |
| Pi | Restart the Pi session; Pi supports several providers enabled at the same time |

> 💡 Terminals started via "Open Terminal" inside CC Switch take effect immediately, no reopen needed.

### Claude Code First Launch Prompt

If Claude Code prompts you to **log in** or shows an onboarding wizard on first launch, enable the "Skip Claude Code first-run confirmation" option in CC Switch:

1. Open CC Switch "Settings > General"
2. Enable the "Skip Claude Code first-run confirmation" toggle
3. Restart Claude Code

![image-20260108002626389](../../assets/image-20260108002626389.png)

> ⚠️ **Note**: This option writes `hasCompletedOnboarding = true` to `~/.claude.json`, skipping the official onboarding flow.

## Verify Configuration

After reopening the terminal, launch the corresponding CLI tool and enter a simple question to test:

```bash
# Claude Code - enter a test question after launching
claude
> Hello, please briefly introduce yourself

# Codex - enter a test question after launching
codex
> Hello, please briefly introduce yourself

# Pi - enter a test question after launching
pi
> Hello, please briefly introduce yourself
```

If the AI responds normally, the configuration is successful.

## Common Issues

### Not taking effect after switching?

Reopen the terminal first. Switching writes user environment variables, while running terminal processes still inherit the old values. If it still does not take effect, check whether `~/.claude/settings.local.json` or the project-level `.claude/settings.json` defines `env.ANTHROPIC_*` — those override process environment variables, and CC Switch will not rewrite those files for you, it only warns about the conflict. See [5.4 Environment Variable Conflicts](../5-faq/5.4-env-conflict.md).

### Can't find a preset?

If your provider is not in the preset list, select "Custom" for manual configuration. See [Add Provider](../2-providers/2.1-add.md) for configuration format details.

### How to restore official login?

Select the "Official Login" preset (Claude / Codex), reopen the terminal, and follow the CLI's own login flow. CC Switch no longer handles OAuth login and does not overwrite your own ChatGPT sign-in state in the Codex `auth.json`.

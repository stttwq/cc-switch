# 1.5 个性化配置

本节介绍如何根据个人偏好配置 CC Switch。

## 打开设置

- 点击左上角 **⚙️** 按钮
- 或使用快捷键 `Ctrl + ,`

## 语言设置

CC Switch 支持四种语言：

| 语言     | 说明     |
| -------- | -------- |
| 简体中文 | 默认语言 |
| 繁體中文 | 繁体中文界面 |
| English  | 英文界面 |
| 日本語   | 日文界面 |

切换语言后立即生效，无需重启。

## 主题设置

| 选项     | 说明                        |
| -------- | --------------------------- |
| 跟随系统 | 自动匹配系统的深色/浅色模式 |
| 浅色     | 始终使用浅色主题            |
| 深色     | 始终使用深色主题            |

## 窗口行为

### 开机自启

开启后，系统启动时自动运行 CC Switch（Windows 下通过注册表实现）。

### 关闭行为

| 选项         | 说明                         |
| ------------ | ---------------------------- |
| 最小化到托盘 | 点击关闭按钮时隐藏到系统托盘 |
| 直接退出     | 点击关闭按钮时完全退出应用   |

推荐使用「最小化到托盘」，方便通过托盘快速切换供应商。

### 静默启动

开启后，程序启动时不显示主窗口，仅在托盘运行。

### 轻量模式

「轻量模式」是一种**仅托盘运行**的状态，用于把空闲时的桌面占用降到最低。

**触发方式**：右键系统托盘图标 → 点击「轻量模式」。主窗口会被**销毁**（而不是隐藏），UI 资源和内存随之释放。

**退出方式**：从托盘菜单点击「打开主界面」。窗口会按需**重建**，状态保持一致。

| 特性         | 最小化到托盘         | 轻量模式                 |
| ------------ | -------------------- | ------------------------ |
| UI 进程      | 保留在内存中         | 完全销毁                 |
| 空闲资源占用 | 与正常运行相当       | 接近零                   |
| 再次打开速度 | 瞬时（直接显示）     | 略慢（需要重建窗口）     |
| 托盘切换功能 | 可用                 | 可用                     |

> 💡 **使用场景**：如果你 CC Switch 长时间常驻后台，主要通过托盘菜单切换供应商，开启轻量模式能显著降低内存占用。

> ⚠️ **注意**：轻量模式状态不持久 — 下次正常启动时会回到普通模式。需要长期使用可搭配开机自启。

### Claude 插件集成

开启后，CC Switch 在切换供应商时会自动同步配置到 VS Code 中的 Claude Code 插件（写入 `~/.claude/config.json` 的 `primaryApiKey`）。

> 💡 **使用场景**：如果你同时使用 Claude Code CLI 和 VS Code 插件，开启此选项可以保持两者配置一致。

### 跳过 Claude 引导

开启后，跳过 Claude Code 的新手引导流程，适合已熟悉 Claude Code 的用户。

> ⚠️ **注意**：此选项会向 `~/.claude.json` 写入 `hasCompletedOnboarding = true`。

### 应用可见性

选择在应用切换器中显示哪些应用。每个应用可以独立开关，但至少保留一个。

可配置的应用：Claude、Codex、Pi。

> 💡 **使用场景**：如果你只使用 Claude Code 和 Codex CLI，可以隐藏 Pi，保持界面简洁。

### Skills 同步方式

设置技能安装到各应用目录时的同步方式：

| 方式              | 说明                                                 |
| ----------------- | ---------------------------------------------------- |
| 软链接（Symlink） | 创建符号链接指向技能源文件，占用空间小，更新实时同步 |
| 复制（Copy）      | 将技能文件完整复制到目标目录                         |

> 💡 **推荐**：默认使用软链接方式。如果遇到权限问题，可切换为复制方式。

### 终端设置

选择 CC Switch 打开终端时使用的终端应用程序。

Windows 支持的终端：CMD、PowerShell、Windows Terminal、自定义终端。

选择「自定义终端」后需填写可执行文件路径和启动参数模板。模板中的 `{bat}` 会被替换为启动脚本路径，留空默认为 `"{bat}"`。例如 Alacritty：路径填 `C:\Program Files\Alacritty\alacritty.exe`，参数模板留空即可。

> 💡 **提示**：从 CC Switch「打开终端」启动的会话会直接注入当前供应商的凭据环境变量，不需要重开终端就能看到新值。

## 目录配置

### 应用配置目录

CC Switch 自身数据的存储位置。Windows MSI 安装版默认使用安装目录下的 `data` 文件夹；首次启动会从 `%USERPROFILE%\.cc-switch\` 复制旧数据（旧目录保留作备份）。开发版默认使用 `%USERPROFILE%\.cc-switch\`。完全卸载时会删除安装目录中的 `data` 和旧默认用户数据目录，升级时保留；手动指定的自定义目录不会被卸载器删除。

### CLI 工具目录

可以自定义各 CLI 工具的配置目录：

| 配置          | 默认值         | 说明                 |
| ------------- | -------------- | -------------------- |
| Claude 目录   | `~/.claude/`   | Claude Code 配置目录 |
| Codex 目录    | `~/.codex/`    | Codex 配置目录       |
| Pi 目录       | `~/.pi/agent/` | Pi 配置目录          |

> ⚠️ **注意**：修改目录后需要重启应用（应用会提示「重启应用」），且对应的 CLI 工具也需要配置相同的目录。

## 数据管理

### 导出配置

点击「导出」按钮，保存包含以下内容的 SQL 备份文件：

- 所有供应商配置（**不含密钥**，密钥只在 Windows 凭据管理器里）
- MCP 服务器配置
- Prompts 预设
- 应用设置

导出文件名格式为 `cc-switch-export-{timestamp}.sql`。

导出时 CC Switch 会扫描文本，一旦发现疑似密钥字面量就拒绝导出，作为回归防线。

### 导入配置

1. 点击「选择文件」
2. 选择之前导出的备份文件
3. 点击「导入」
4. 确认覆盖现有配置

> ⚠️ **注意**：导入会覆盖现有配置，建议先导出当前配置作为备份。导入旧版本导出的 SQL（里面可能带明文密钥）时，CC Switch 会在导入完成后把这些密钥提取进凭据管理器并从数据库里剥离。

## 全局出站代理

设置 → 高级 中的「全局出站代理」，为 WebDAV/S3 同步与 Skills 下载等出站请求配置 HTTP/HTTPS 代理。它**不**转发任何 CLI 请求，也不监听任何本地端口。出于安全考虑，代理 URL 不允许内嵌 `user:pass@` 凭据；旧值若含认证信息，会在升级迁移时整键作废并提示重填。

## 高级设置

设置 → 高级 Tab

### 配置目录

自定义各应用的配置文件目录。详见上方「目录配置」章节。

### 数据管理

导入/导出配置备份。详见上方「数据管理」章节。

### 备份与恢复

备份管理面板提供对数据库备份的全面控制。

#### 自动备份设置

| 配置     | 选项                               | 默认值    |
| -------- | ---------------------------------- | --------- |
| 备份间隔 | 禁用、6h、12h、24h、48h、7d        | 24 小时   |
| 保留数量 | 3、5、10、15、20、30、50           | 10 个备份 |

设置间隔后，CC Switch 会按计划自动备份数据库。超出保留数量的旧备份会自动删除。

#### 备份列表

面板显示所有现有备份，包含：
- **显示名称**（根据时间戳自动生成，如 `db_backup_20260315_143000`）
- **创建时间**
- **文件大小**（如 "1.5 MB"）

#### 备份操作

| 操作         | 说明                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| **立即备份** | 立即创建一个备份                                                         |
| **恢复**     | 从选定的备份恢复数据库。恢复前会自动创建当前数据库的安全备份             |
| **重命名**   | 修改备份的显示名称                                                       |
| **删除**     | 永久删除备份（需确认）                                                   |

> ⚠️ **重要**：恢复备份会覆盖当前数据库。恢复操作前始终会自动创建安全备份，以便在需要时恢复。

#### 升级前的回滚备份

从旧版本升级时，数据库会从 schema v18 升到 v19，升级前自动生成一份 `pre-secrets-migration-*.db`。这份备份含迁移前的明文，因此**不会自动删除**，仅用于回滚到旧版本；确认无误后可在备份列表里手动删除。

### 云同步（WebDAV / S3）

通过 WebDAV 或 S3 兼容存储在多台设备间同步配置。默认使用 **v2 协议**（双层版本控制）；开启端到端加密后改用 **v3** 布局（见下）。

| 配置项   | 说明                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 服务预设 | 坚果云 / Nextcloud / 群晖 / 自定义（WebDAV）；AWS S3 / MinIO / R2 / OSS / COS 等（S3） |
| 服务地址 | 服务器 URL / Endpoint                                                        |
| 用户名   | 登录用户名                                                                   |
| 密码     | 登录密码（应用专用密码）。**保存在 Windows 凭据管理器**，不写进 `settings.json`，也不随同步上传 |
| 远程目录 | 远程存储路径（默认 `cc-switch-sync`）                                        |
| 配置名称 | 设备配置文件名（默认 `default`）                                             |
| 自动同步 | 开启后按配置的间隔自动同步                                                   |

S3 的 Access Key ID 与 Secret Access Key 同样存放在 Windows 凭据管理器。

#### 同步不包含密钥

同步载荷里没有任何供应商凭据。在另一台设备还原后，所有供应商卡片会显示「需要密钥」徽标，切换会被拒绝并提示先补全 API Key —— 这是设计行为，不是 bug。

#### 操作

| 操作         | 说明                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| **测试连接** | 验证服务地址与凭据是否有效                                                                   |
| **上传**     | 将本地数据库上传到远程，显示进度指示器                                                       |
| **下载**     | 下载远程数据库。下载前显示远程快照信息（协议版本、数据库版本、时间戳、大小）供确认。覆盖本地数据库前会自动创建安全备份 |

#### 自动同步

启用 **自动同步** 后：
- 首次激活时会显示确认对话框
- CC Switch 按配置的间隔自动将数据库同步到远端
- 面板中显示同步状态

#### 远程快照信息

下载前，CC Switch 会显示远程快照的详细信息：
- 协议版本（v2）
- 数据库兼容版本
- 远程备份的时间戳
- 文件大小
- 兼容性状态（不兼容时显示警告）

> ⚠️ **注意**：上传会覆盖远程数据，下载会覆盖本地数据。下载前始终会自动创建安全备份。

#### 端到端同步加密（E2E）

「设置 → 高级 → 云同步」的**端到端加密**小节可为 WebDAV / S3 分别开启。开启后同步载荷在**本机**加密，只有用同一口令的另一台设备才能解密，服务器（含托管商）只能看到密文。

- **口令**：在加密小节内联输入，保存到 Windows 凭据管理器，**永不上传**、不再回显。口令经 Argon2id 派生主密钥，再用随机数据密钥（XChaCha20-Poly1305）加密 `db.sql` 与 `skills.zip`；每份快照带单调递增序号，可防回滚与篡改。
- **忘口令 = 不可恢复**：远端密文没有任何找回途径。若要换机又忘了口令，只能在原设备用「停用并清空远端」重新初始化。
- **仍不同步密钥**：加密载荷里没有供应商凭据，还原后照样显示「需要密钥」。
- **并存与迁移**：v3 与 v2 分目录存放，2.0 客户端读不到 v3、开了加密的本机也拒绝降级读 v2 明文。请**所有设备都升级到本版本后再开启**；迁移完成后可用「删除旧版明文快照」清理远端遗留的 v2 明文。
- **传输安全**：`http` 明文端点默认拒绝，仅本机/内网地址在勾选「允许不安全连接」后放行；升级前已配置 http 的远端会一次性豁免。

### 安全：严格投递模式（分级）

默认情况下，切换供应商会把当前供应商的密钥写入用户环境变量（`HKCU\Environment`），供本机命令行工具读取——这是同用户任何进程都能读到的既定边界。

「设置 → 高级 → 安全」的**严格投递模式**（默认关）改变这一行为。v2.2 起它从"单个开关"升级为三档：

- **关**：常规投递，切换即写环境变量。
- **按应用**：仅对勾选的 `Claude` / `Codex` / `Pi` 严格，其余应用照常写入。适合"只有高敏应用需要严格"的场景。
- **全局**：所有应用都严格。

任一形态对某应用严格时：

- 切换该应用的供应商**不再写环境变量**，开启瞬间会**立即收回**该应用此前已投递到用户环境变量的密钥（"按应用"只收回转为严格的应用，不误伤仍宽松的应用）。
- 从别处（系统终端、其他启动器）启动的对应 CLI 将读不到密钥，会因缺少凭据而报错（fail-closed）。

**在自己的终端里激活凭据（v2.2 新增 `ccs env`）**：严格模式不再把你赶出自己的工作流。在设置面板点「复制激活命令」，把一次性片段接入 `$PROFILE` / `.bashrc`（不改系统 PATH），随后在任意 shell 里：

```powershell
# PowerShell
ccs-use claude        # 等价于：ccs env claude | Invoke-Expression
ccs-use claude --clear   # 只清除，不注入
```
```bash
# bash / Git Bash
eval "$(ccs env claude --shell bash)"
```

密钥只进入当前 shell 进程内存，关闭即消失，注册表始终无明文——与「打开终端」同一安全边界。cmd 为 best-effort（`for /f` 用法见命令输出）。退出码约定：`0` 成功、`2` 用法错误、`3` 缺密钥、`4` 数据库版本不符、`5` 凭据库/配置不可用。

> ⚠️ `ccs.exe` 随安装包分发需在真实 MSI 构建中确认（与 GUI 同目录）。

### 日志配置

| 配置项   | 说明                                |
| -------- | ----------------------------------- |
| 启用日志 | 开启/关闭应用日志记录               |
| 日志级别 | error / warn / info / debug / trace |

日志级别说明：

- **error** - 仅记录错误
- **warn** - 记录警告和错误
- **info** - 记录一般信息（推荐）
- **debug** - 记录调试信息
- **trace** - 记录所有详细信息

日志不会写入任何密钥值。

### 凭据管理器维护

设置 → 高级 → 「凭据管理器维护」，用于清理已删除供应商在 Windows 凭据管理器里残留的条目。

> 💡 由于 Windows 凭据管理器不支持枚举，此功能依据 CC Switch 自己记录的条目名清单来清理；手动在别处创建的条目不会被它碰。

## 关于页面

设置 → 关于 Tab

### 版本信息

显示当前 CC Switch 版本号，并提供发布说明入口。

CC Switch 没有应用内更新功能：不会在启动时检查新版本，也不会提示下载。要升级到新版本，请到 [GitHub Releases](https://github.com/stttwq/cc-switch/releases) 下载新的 Windows 安装包并覆盖安装。

### 本地环境检查

自动检测已安装的 CLI 工具版本：

| 工具     | 检测内容           |
| -------- | ------------------ |
| Claude   | 当前版本、最新版本 |
| Codex    | 当前版本、最新版本 |
| Pi       | 当前版本、最新版本 |

点击「刷新」按钮可重新检测；检测到新版时可单独升级，也可以点击「全部升级」。未检测到的工具会显示安装按钮。安装与升级在后台静默执行，按钮上会显示进度，完成后自动刷新版本。

### 手动安装命令

提供快速安装/升级 CLI 工具的命令（该区域默认折叠，点击标题展开）：

```bash
npm i -g @anthropic-ai/claude-code@latest
npm i -g @openai/codex@latest
npm i -g @earendil-works/pi-coding-agent@latest
```

点击「复制」按钮可复制到剪贴板。

# 4.1 1Password 凭据后端

> 适用于 CC Switch v2.3.0 及以上（可选功能，默认仍使用 Windows 凭据管理器）。

CC Switch 支持把所有钥匙（供应商 API Key、额外环境变量、Pi 敏感请求头、WebDAV 密码、S3 两把、E2E 同步口令）从 Windows 凭据管理器迁移到 [1Password](https://1password.com/)，由本机 1Password CLI（`op`）经桌面 App 按需取用。本地数据库、内存、凭据管理器、注册表都不再留任何钥匙明文。

## 启用条件

- 已安装 1Password 桌面版并登录；
- 已安装 1Password CLI（`op.exe`），并在 1Password 设置中开启「与 CLI 集成」（开发者选项）；
- 在「设置 → 高级 → 1Password」中加载账户、选择 vault，并可勾选「校验 op.exe 签名」（推荐，默认开）。

CC Switch 会校验 `op.exe` 的 Authenticode 签名，签名者必须完整等于 `Agilebits`；校验失败会拒绝执行，绝不把钥匙交给来路不明的二进制。

## 迁移（单向）

点「迁移到 1Password」后，CC Switch 会把凭据管理器里所有 `cc-switch/*` 条目逐组：写入 1Password → 回读校验 → 删除凭据管理器条目并清理注册表投递。先写后删、可中断可重跑，每组完成后界面上报进度（约 7 秒/组）。

- **迁移是单向的（D10）**：没有「切回凭据管理器」的开关。切换完成后必须立即重启 CC Switch（界面只提供「立即重启」一个选项）。
- 迁移后 1Password 是唯一真源。「清理凭据管理器残留」按钮可以把迁移后仍残留在凭据管理器里的 `cc-switch/*` 条目删掉（动作前会要求确认）。
- 已迁移后再次迁移会被拒绝。

## 迁移后的行为

- **列表、启动、状态查询 0 次 op**：打开主界面、浏览供应商、切换（在钥匙已在 live 中的情况下）不需要 1Password 解锁。
- **取钥匙才请求解锁**：打开终端、运行 CLI、显示明文、同步等动作会现取现用、用完即丢弃（`Zeroizing`），不做跨操作缓存。可能弹出 1Password 授权，界面统一显示「正在向 1Password 请求，可能需要解锁…」。
- **base_url 也存进 1Password（D3-B）**：供应商端点随整包写入 vault 条目（非敏感 URL 在 1Password 里以可见字段展示，可直接核对）；本地端点表只是读取缓存，命中时 0 次 op。**1Password 是钥匙 + 端点的持久真源**——数据库被重置或换设备后，执行「从 1Password 重建引用」即可整体恢复（引用与端点一起回来）。带凭据的 URL（如 `user:pass@host` 或 query 参数里带钥匙的）以隐藏字段存进 1Password。
- **1Password 模式下强制严格投递**：钥匙绝不写 `HKCU\Environment`（注册表同账号程序可读）；只注入 CC Switch 拉起的终端或经 `ccs env` 注入。
- **自动同步停用**：1Password 模式下后台自动云同步跳过（避免周期性解锁弹窗），手动同步照常可用，界面会显示说明。
- **凭据便携包**：导出不可用（1Password 自带跨设备同步）；导入仍可用，导入的钥匙会写进 1Password。
- **条目标题**：vault 条目标题就是你在 CC Switch 里起的供应商名（改名后下次保存该供应商时同步）；条目里的 `cc-switch-group` 字段承载内部标识，请勿删除或修改它。

## 检测到明文时（不丢弃原则）

在 1Password 模式下，如果 CC Switch 在 Pi `models.json`、live 配置文件或导入数据里发现明文钥匙，但无法立即安全收进 vault（比如 1Password 正处于锁定状态），**不会丢掉也不会静默写坏**，而是保留原样并记入待办，主界面出现横幅提示「导入到 1Password」。点击导入会把明文收进 vault 并把原文件改写为引用；写入失败的行保留明文，解锁 1Password 后重试即可。

## 换设备 / 云同步恢复 / 数据库重置后

本地引用表（`secret_refs`，只记条目 id 与字段名清单，不含值）**不随云同步**。在新设备上恢复配置、或本地数据库被重置后，请执行「设置 → 高级 → 凭据维护 → 从 1Password 重建引用」：CC Switch 会枚举 vault 中带 `cc-switch` 标签的条目、读取条目内的 `cc-switch-group` 归属字段重建引用，端点（base_url）也随之恢复进本地缓存（约 N+1 次 op，可能请求解锁）。之后每次切换仍可能有一次端点懒加载，属正常现象。

## 多设备：1Password 同步钥匙和端点，CCS 云同步 / SQL 只同步配置

同一个 1Password 账户（同一 vault）的多台设备之间，钥匙和端点由 1Password 自己加密同步；CC Switch 的云同步（WebDAV / S3）与手动 SQL 导入导出只搬运**配置**，不搬运钥匙。各类数据的去向：

| 数据 | 去向 |
|---|---|
| 供应商、MCP、提示词、Skills、模型设置等配置 | 随 CCS 云同步 / SQL 导入导出 |
| 钥匙（API Key、额外环境变量、敏感请求头、同步口令等） | 只在 1Password，CCS 从不同步 |
| 端点 base_url（非敏感 URL） | 在 1Password 条目里；本机端点表只是缓存，1P 模式下不随 CCS 同步 / SQL 导出离开本机 |
| 引用表 `secret_refs` | 本机保留；SQL / 快照里只带 1P 引用行，且只在**两边是同一 vault** 时才被采纳 |

- **「未关联」是什么意思**：从其他设备同步来的供应商，如果本机引用表里没有对应行（不同 vault、或导入的文件没带引用），列表会显示「未关联」而不是「缺钥匙」。这时**不需要重新输入钥匙**——点横幅上的「从 1Password 关联」，CC Switch 会在 vault 里按归属字段找到条目重建引用；找不到的（1P 里确实没有）才需要补钥匙。
- **端点对账**：怀疑端点不对时，可在「设置 → 高级 → 1Password → 诊断」执行端点对账：逐个供应商比较 vault 与本机缓存的 base_url（只显示分歧清单，不显示 URL），可一键「以 1Password 为准」校正缓存或「以本机缓存为准」写回 1Password。对账同时会校验设置里的 vault 值是否真实存在。
- **同一账户、不同 vault 的两台设备**：引用不采纳（有意的安全边界），需要手动「从 1Password 关联」。
- 已知边界：Codex 非当前供应商表里的 base_url、Pi `models[].baseUrl`、以及用户手写在通用配置片段里的 URL 属于配置文本，会随 CCS 同步走。

## 1Password 不可用时

1Password 锁定、未运行、断网或授权被取消时，需要钥匙的操作**明确报错**（绝不静默降级为「没有钥匙」），错误提示带「重试」按钮。处理方式：

- **锁定 / 取消授权**：打开 1Password 解锁后点「重试」；`ccs env` 退出码为 `6`；
- **断网 / 超时**：恢复网络后重试；`ccs env` 退出码为 `7`；
- 其余分类见 `ccs env` 退出码表（[1.5 个性化配置](../1-getting-started/1.5-settings.md)）。

锁定期内任何人（包括 CC Switch 自己）都拿不到钥匙；CC Switch 的浏览、编辑非敏感字段等功能仍可正常使用。

## 诚实边界

**能防：**

- 拷走硬盘 / 数据库 / 备份拿不到钥匙；
- 同账号程序翻凭据管理器、翻注册表拿不到（凭据管理器已清空、注册表不再投递）；
- 1Password 锁定期间，任何人（含 CC Switch 自己）拿不到。

**防不住：**

- **已注入钥匙的终端进程**：它的环境块里有明文，同账号程序可以读子进程环境——这是「给 CLI 工具用钥匙」的物理下限；
- **Codex / Pi 的 Base URL** 会以明文写进它们自己的配置文件（工具本身只认文件里的 URL）；
- 1Password 解锁窗口内，同账号的恶意程序也能调用 `op`（1Password 的 App 集成按进程弹授权，会有提示，但用户可能误点）;
- CC Switch 进程内在取钥匙到注入完成的几秒里存在明文（用完即 `Zeroizing` 丢弃）。

## 卸载

**卸载 CC Switch 不会删除你 1Password vault 里的任何条目（D5）**——那些条目属于你的 1Password 账号，手动清理即可。卸载流程只清理本机数据（凭据管理器条目、注册表投递、配置文件等）。

## 版本要求

数据库 schema 升级到 v21 后，必须先用 GUI 启动一次完成迁移，`ccs env` / 右键菜单才能使用（CLI 会拒绝过新或过旧的数据库版本）。

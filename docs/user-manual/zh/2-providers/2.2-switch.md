# 2.2 切换供应商

## 主界面切换

在供应商列表中，点击目标供应商卡片的「启用」按钮。

### 切换流程

1. 点击「启用」按钮
2. CC Switch 从 Windows 凭据管理器读出该供应商的密钥，写入用户级环境变量，并重写 live 配置文件
3. 卡片状态变为「当前启用」
4. **已打开的终端需要重开**，新变量才会被读到

> ⚠️ 如果该供应商还没有密钥（例如刚从另一台设备同步还原），切换会被拒绝并提示先补全 API Key。

**不想重开终端？** v2.2 起 Claude / Codex / Pi 三种应用的供应商卡片都有终端入口（密钥只注入到 CC Switch 自起的终端进程，不落 `HKCU\Environment`）：

- **「打开终端」**：设好该供应商凭据后，落入一个**带环境的交互式 shell**，不自动跑 CLI——你自己敲命令、`cd`、开多个工具都行。
- **「运行 X」**：设好凭据后直接起对应 CLI（Claude→`claude`、Codex→`codex`、Pi→`pi`）。

若开启了**严格投递模式**，从别处启动的 CLI 拿不到密钥；可在自己的 shell 里用 `ccs env <app>` 激活（见 [设置 → 严格投递模式](../1-getting-started/1.5-settings.md)）。

### 状态指示

| 状态 | 显示 | 说明 |
|------|------|------|
| 当前启用 | 蓝色边框 + 标签 | 当前使用的供应商 |
| 需要密钥 | 提示徽标 | 密钥缺失（如同步还原后），需编辑供应商补全 |
| 普通 | 默认样式 | 未启用的供应商 |

## 托盘快速切换

通过系统托盘可以快速切换，无需打开主界面。

### 操作步骤

1. 右键点击系统托盘的 CC Switch 图标
2. 将鼠标悬停在对应应用的子菜单上（如 "Claude · 当前供应商"）
3. 点击要切换到的供应商名称
4. 切换完成，托盘会短暂提示

> ⚠️ 托盘切换走的是同一套投递路径（用户级环境变量），因此**已打开的终端同样需要重开**。

### 托盘菜单结构

托盘菜单是**按应用分组的分级子菜单**，为每个应用独立建立子菜单：

| 子菜单      | 说明                     |
| ----------- | ------------------------ |
| Claude      | Claude 所有供应商        |
| Codex       | Codex 所有供应商         |
| Pi          | Pi 所有供应商            |

**分级子菜单的好处**：

- **防止菜单溢出**：有大量供应商时，扁平列表会超出屏幕高度；分级子菜单天然支持无限扩展
- **子菜单标题显示当前激活供应商**：无需打开子菜单即可知道 Claude / Codex / Pi 当前使用哪个供应商
- **按应用隔离操作**：切换 Claude 的供应商不会干扰到 Codex 或 Pi 的视图

> 💡 **提示**：后台常驻 + 轻量模式 + 分级子菜单的组合特别适合频繁切换多个应用的重度用户。参考 [1.5 个性化配置 → 轻量模式](../1-getting-started/1.5-settings.md)。

## 生效方式

三个应用的凭据都通过**用户级环境变量**投递，因此共同点是：**新开的终端才看得到新值**。

### Claude Code

- CC Switch 把 `ANTHROPIC_AUTH_TOKEN`（或 `ANTHROPIC_API_KEY`，取决于供应商的认证字段）与 `ANTHROPIC_BASE_URL` 写入 `HKCU\Environment`，并广播 `WM_SETTINGCHANGE`
- `~/.claude/settings.json` 中不再包含这些键，因此不会覆盖环境变量
- 关闭并重新打开终端即生效

### Codex

- 第三方供应商：CC Switch 写入 `CC_SWITCH_CODEX_API_KEY` 环境变量，`~/.codex/config.toml` 的对应 `[model_providers.<id>]` 表里只写 `env_key = "CC_SWITCH_CODEX_API_KEY"` 和 `base_url`
- 官方 API Key 供应商：写入 `OPENAI_API_KEY`
- 关闭并重新打开终端即生效

### Pi

- 每个启用的 Pi 供应商各有自己的变量 `CC_SWITCH_PI_<KEY>_API_KEY`，`~/.pi/agent/models.json` 里写 `apiKey: "$CC_SWITCH_PI_<KEY>_API_KEY"`
- Pi 支持多个供应商同时启用，启用 / 移除单个供应商只增删自己的变量
- 重新打开 Pi 会话即可看到变化

## 配置文件变更

切换供应商时，CC Switch 会修改以下内容。

### Claude

| 位置 | 变更 |
|------|------|
| `HKCU\Environment`（用户级环境变量） | 写入 `ANTHROPIC_*`；从不写 `HKLM` |
| `~/.claude/settings.json` | 写入剥离后的配置（模型名等非敏感 env），**不含** `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL` |

### Codex

| 位置 | 变更 |
|------|------|
| `HKCU\Environment` | 写入 `CC_SWITCH_CODEX_API_KEY`（第三方）或 `OPENAI_API_KEY`（官方） |
| `~/.codex/config.toml` | 写入 `env_key` 变量名与当前供应商的 `base_url`；不含 `experimental_bearer_token` |

> 💡 CC Switch 不再写 `~/.codex/auth.json`，你自己用 `codex login` 建立的登录态不会被覆盖。

### Pi

| 位置 | 变更 |
|------|------|
| `HKCU\Environment` | 写入 `CC_SWITCH_PI_<KEY>_API_KEY`（及敏感 header 变量） |
| `~/.pi/agent/models.json` | 写入供应商节点，`apiKey` 为 `$变量名`，`baseUrl` 为实际地址 |

> ℹ️ Codex 与 Pi 的 `base_url` 只能写在 live 文件里（对应 CLI 不支持在该字段做变量引用），且只写当前激活的那一个；其它供应商的 Base URL 仍只在凭据管理器里。

## 切换失败处理

如果切换失败，可能的原因：

### 缺少密钥

供应商没有保存过 API Key（新建时留空，或从其它设备同步还原）。

**解决方法**：编辑该供应商，重新输入密钥并保存。

### 环境变量冲突

用户级环境里已有同名变量且不是 CC Switch 写的，值也不同。CC Switch 会先弹冲突对话框，只显示对方变量的末 4 位。

**解决方法**：确认「接管（覆盖）」后重跑切换，或取消切换自行处理。注意接管后原值会被覆盖且不保留。详见 [5.4 环境变量冲突](../5-faq/5.4-env-conflict.md)。

### 配置文件被锁定

其他程序正在使用配置文件。

**解决方法**：关闭正在运行的 CLI 工具，再尝试切换。

### 权限不足

没有写入配置文件的权限。

**解决方法**：检查配置目录的权限设置。

### 配置格式错误

供应商配置的 JSON 格式有误。

**解决方法**：编辑供应商，检查并修复 JSON 格式。

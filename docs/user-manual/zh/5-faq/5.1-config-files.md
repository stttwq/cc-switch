# 5.1 配置文件说明

## CC Switch 数据存储

### 存储目录

默认位置：`~/.cc-switch/`（Windows 上即 `%USERPROFILE%\.cc-switch\`）

可在设置中自定义位置（用于云同步）。

### 目录结构

```
~/.cc-switch/
├── cc-switch.db      # SQLite 数据库（SSOT，不含任何密钥）
├── settings.json     # 设备级设置（不含任何密钥）
├── logs/             # 运行日志（已脱敏）
├── crash.log         # 崩溃记录
├── skills/           # 技能 SSOT 目录
├── skill-backups/    # 技能备份（卸载时创建）
└── backups/          # 数据库备份
```

### 凭据在哪里

**不在这些文件里。** API Key、端点地址与被判定为敏感的环境变量，唯一持久化位置是 **Windows 凭据管理器**（Credential Manager），条目名以 `cc-switch/` 为前缀。数据库、`settings.json`、导出文件、同步载荷与日志中都没有密钥值。

### 数据库内容

`cc-switch.db` 是 SQLite 数据库，存储：

| 表 | 内容 |
|-----|------|
| providers | 供应商配置（已剥离密钥与端点地址） |
| mcp_servers | MCP 服务器配置 |
| prompts | 提示词预设 |
| skills | 技能安装状态 |
| skill_repos | 技能仓库配置 |
| profiles | 配置快照 |
| settings | 应用设置与环境变量所有权记录 |

### 设备设置

`settings.json` 存储设备级设置：

```json
{
  "language": "zh",
  "theme": "system",
  "minimizeToTrayOnClose": true,
  "launchOnStartup": false,
  "visibleApps": { "claude": true, "codex": true, "pi": true },
  "claudeConfigDir": null,
  "codexConfigDir": null,
  "piConfigDir": null,
  "skillSyncMethod": "auto",
  "skillStorageLocation": "cc_switch",
  "backupIntervalHours": 24,
  "backupRetainCount": 10,
  "preferredTerminal": "wt"
}
```

这些设置不会跨设备同步。WebDAV 密码与 S3 Access Key 也不在这里——它们在 Windows 凭据管理器中。

### 自动备份

`backups/` 目录存储自动备份：

- 按计划创建（间隔与保留数量可配置）
- 默认保留最近 10 个备份
- 文件名包含时间戳
- 备份现在不含密钥，可以安全保存与分享

升级时还会额外生成一份 `pre-secrets-migration-*.db`（迁移前的 v18 库，含明文），仅用于回滚，不会自动删除。

## 环境变量投递

CC Switch 只写**用户级**环境变量（注册表 `HKCU\Environment`），从不写 `HKLM`，并在批量写入后广播 `WM_SETTINGCHANGE`。

| 用途 | 变量名 |
|------|--------|
| Claude API Key | `ANTHROPIC_AUTH_TOKEN` 或 `ANTHROPIC_API_KEY` |
| Claude 端点 | `ANTHROPIC_BASE_URL` |
| Codex 第三方 API Key | `CC_SWITCH_CODEX_API_KEY` |
| Codex 官方 API Key | `OPENAI_API_KEY` |
| Pi API Key | `CC_SWITCH_PI_<KEY>_API_KEY` |
| Pi 敏感 header | `CC_SWITCH_PI_<KEY>_HEADER_<NAME>` |

哪些变量是 CC Switch 写的，记录在数据库 `settings` 表的 `managed_env_vars` 键里。

## Claude Code 配置

### 配置目录

默认：`~/.claude/`

### 主要文件

```
~/.claude/
├── settings.json     # 主配置文件
├── CLAUDE.md         # 系统提示词
└── skills/           # 技能目录
    └── ...
```

### settings.json

```json
{
  "env": {
    "ANTHROPIC_MODEL": "kimi-k2.7-code",
    "CLAUDE_CODE_MAX_CONTEXT_TOKENS": "262144"
  }
}
```

> ⚠️ **注意**：CC Switch 写这个文件时**不会**再写入 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL`。Claude Code 直接从进程环境读取它们，因此这些值走环境变量投递。写入前还有一道护栏，检测到敏感键会拒绝写入。

如果你在 `~/.claude/settings.local.json` 或项目级 `.claude/settings.json` 里自己写了 `env.ANTHROPIC_*`，**它们会覆盖进程环境变量**。CC Switch 不改这些文件，只会给出只读冲突告警。

### MCP 配置

MCP 服务器配置在 `~/.claude.json`：

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Codex 配置

### 配置目录

默认：`~/.codex/`

### 主要文件

```
~/.codex/
├── auth.json         # 你自己的 Codex 登录态（CC Switch 不写）
├── config.toml       # 主配置 + MCP
├── AGENTS.md         # 系统提示词
├── skills/           # 技能目录
└── sessions/         # 会话记录
```

### config.toml

```toml
model_provider = "custom"
model = "gpt-5.2"

[model_providers.custom]
name = "custom"
base_url = "https://api.example.com/v1"
wire_api = "responses"
env_key = "CC_SWITCH_CODEX_API_KEY"
```

| 字段 | 说明 |
|------|------|
| `env_key` | 指向用户级环境变量名的字符串，密钥值不在文件里 |
| `base_url` | 端点地址。**例外**：Codex CLI 不支持在该字段做变量引用，因此当前激活供应商的 Base URL 会写在这里；其余供应商的 Base URL 仍只在凭据管理器里 |

> ⚠️ CC Switch 不再写 `~/.codex/auth.json`，也不会再往 `config.toml` 里写 `experimental_bearer_token`。

## Pi 配置

### 配置目录

默认：`~/.pi/agent/`

### 主要文件

```
~/.pi/agent/
├── models.json       # 供应商与模型配置
├── AGENTS.md         # 系统提示词
├── skills/           # 技能目录
└── sessions/         # 会话记录
```

### models.json

```json
{
  "providers": {
    "example": {
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "$CC_SWITCH_PI_EXAMPLE_API_KEY"
    }
  }
}
```

`apiKey` 只会是 `$变量名` 形式。`baseUrl` 与 Codex 同样是例外——Pi CLI 不支持在该字段做变量引用，因此启用中的供应商会写明文地址。

## 配置优先级

CC Switch 修改配置时的优先级：

1. **Windows 凭据管理器** - 密钥与端点地址的唯一真源
2. **CC Switch 数据库** - 其余配置的单一事实源 (SSOT)
3. **Live 配置文件 / 用户级环境变量** - 切换供应商时写入
4. **回填机制** - 编辑当前供应商时从 Live 文件读取（只回填已剥离的部分）

## 手动编辑配置

### 可以手动编辑

- CLI 工具的配置文件（非敏感部分会被 CC Switch 回填）
- CC Switch 的 `settings.json`

### 不建议手动编辑

- `cc-switch.db` 数据库文件
- 备份文件

### 编辑后同步

如果手动编辑了 CLI 工具的配置：

1. 打开 CC Switch
2. 编辑对应的供应商
3. 会看到手动修改的内容已回填
4. 保存以同步到数据库

> ⚠️ 如果你在 live 文件里手写了明文密钥，CC Switch 在读取/同步时会把它提取进凭据管理器并把文件里的值替换为变量引用。

## 配置迁移

### 从旧版本迁移

升级到当前版本（数据库 schema v19）时，首次启动会自动完成：

1. 生成 `pre-secrets-migration-*.db` 回滚备份
2. 删除已移除应用的供应商 / MCP / skills 行，以及本地路由相关表
3. 把所有供应商的密钥与端点地址迁入 Windows 凭据管理器，从数据库中剥离
4. 把 WebDAV 密码、S3 Access Key 迁入凭据管理器
5. 清理旧版明文残留：`config.json` 及其 `.bak` / `.migrated`、`codex_oauth_auth.json`、`backups/env-backup-*.json`、`%TEMP%\claude_*.json`
6. 重写 live 文件并投递环境变量
7. 弹一次性提示说明迁移结果

迁移是幂等的，中断后下次启动会重跑；凭据管理器不可用时会阻断并报错，不会退回明文写入。

### 跨设备迁移

1. 在源设备导出配置
2. 在目标设备导入配置
3. 或使用云同步功能

> ⚠️ 导出与同步都**不携带密钥**。在目标设备上，所有供应商会显示「需要密钥」，需要逐个补全 API Key 后才能切换。

## 配置备份建议

### 定期备份

建议定期导出配置：

1. 设置 → 高级 → 数据管理
2. 点击「导出」
3. 保存到安全位置

### 备份内容

导出文件包含：

- 所有供应商配置（不含密钥）
- MCP 服务器配置
- Prompts 预设
- 应用设置

### 不包含的内容

- 任何密钥与端点地址（在 Windows 凭据管理器里）
- 设备级设置（不适合跨设备）

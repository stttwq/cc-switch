# 5.4 环境变量冲突

## 功能说明

CC Switch 通过**用户级环境变量**（注册表 `HKCU\Environment`）把凭据投递给 CLI。既然投递靠环境变量，就可能与你自己在别处设置的同名变量冲突，所以 CC Switch 会检测并报告这些冲突。

**检测的变量前缀**：

| 应用 | 匹配前缀 |
|------|----------|
| Claude | `ANTHROPIC*`（如 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL`） |
| Codex | `OPENAI*`（如 `OPENAI_API_KEY`） |

CC Switch 同时在内部记录**哪些变量是它自己写的**（数据库 `settings` 表的 `managed_env_vars`）。自己写的变量再覆盖不算冲突。

## 两种冲突场景

### 切换时的拦截式冲突

切换供应商时，如果将要写入的变量已存在、不是 CC Switch 写的、且值不同 —— CC Switch **不写**，并弹出冲突对话框。

| 字段 | 说明 |
|------|------|
| 变量名 | 环境变量名称 |
| 当前值 | **只展示末 4 位**（形如 `***wxyz`），完整值从不回传到界面 |
| 归属 | `foreign`（外来变量） |

你可以选择：

- **接管（覆盖）**：CC Switch 用新值覆盖它，并把这个变量登记为自己的；随后继续完成切换
- **取消切换**：保持原状，什么都不改

> ⚠️ **重要**：接管后原值会被覆盖**且不保留**——CC Switch 不再为你备份被覆盖的变量值。接管前请确认你不需要那个旧值。

### 常驻的警告横幅

主界面顶部可能显示黄色警告横幅，列出检测到的同名变量。除了注册表来源，它还包含一类**只读**告警：

| 来源 | 说明 | 能否由 CC Switch 删除 |
|------|------|----------------------|
| 用户注册表（`HKEY_CURRENT_USER\Environment`） | Windows 用户级环境变量 | ✅ 可以 |
| 系统注册表（`HKEY_LOCAL_MACHINE\...\Environment`） | Windows 系统级环境变量 | ❌ 只读报告 |
| `~/.claude/settings.local.json` | Claude 自己的本地覆盖文件里的 `env.ANTHROPIC_*` | ❌ 只读报告 |

> 💡 用户级变量在同名时会覆盖系统级变量（`PATH` 除外），所以系统级同名变量通常只影响你不用 CC Switch 的场景。

## 处理冲突

### 选择要处理的变量

1. 勾选要处理的变量（只读来源无法勾选）
2. 或点击「全选」

### 删除变量

1. 点击「删除选中」按钮
2. 确认删除操作
3. CC Switch 会从 `HKCU\Environment` 删除该变量、同步更新本进程环境，并广播 `WM_SETTINGCHANGE`

> ⚠️ **不再自动备份**：早期版本会在删除前把变量值明文备份到文件，这个机制已经移除（明文备份本身就是要修掉的问题）。删除前请自行确认不需要原值。

## 忽略警告

如果确认冲突不影响使用，可以：

1. 点击警告横幅右侧的「关闭」按钮
2. 警告会暂时隐藏
3. 下次启动时会重新检测

## 手动处理

如果不想通过 CC Switch 处理，可以手动操作：

### Windows 用户级变量

1. 打开「系统属性 → 高级 → 环境变量」，或使用 PowerShell
2. 在**用户变量**中找到冲突变量
3. 删除或修改该变量

### 系统级变量

需要管理员权限，CC Switch 一律不碰 `HKLM`。请自行在「环境变量」对话框的系统变量区处理。

### Claude 的本地覆盖文件

`~/.claude/settings.local.json` 与项目级 `.claude/settings.json` 里的 `env.ANTHROPIC_*` 优先级高于进程环境变量，会盖掉 CC Switch 投递的值。CC Switch 不改这些文件，请自行删除或注释掉对应条目。

## 为什么会冲突

环境变量的值由 CLI 在进程启动时读取，可能导致：

- CC Switch 设置的供应商配置被外来值覆盖
- API 请求发送到错误的端点
- 使用错误的 API 密钥

## 最佳实践

1. **让 CC Switch 独占这些变量**：不要在系统环境变量或 shell 配置里另外设置 `ANTHROPIC_*` / `OPENAI_API_KEY`
2. **定期检查**：关注冲突警告，及时处理
3. **接管前确认旧值**：被覆盖的原值不再由 CC Switch 保管
4. **改完重开终端**：CC Switch 会广播 `WM_SETTINGCHANGE`，但只有新开的进程能读到

## 撤销接管

如果接管了某个你其实想保留的变量：

1. 编辑并切换到别的供应商，或直接删除该供应商 —— CC Switch 会移除它登记的变量
2. 在「设置 → 高级 → 凭据管理器维护」里清理可能残留的凭据条目
3. 原值需要你自行恢复（例如从你自己的备份、或供应商控制台重新获取）

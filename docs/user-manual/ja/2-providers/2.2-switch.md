# 2.2 プロバイダーの切り替え

## メイン画面での切り替え

プロバイダーリストで、対象のプロバイダーカードの「有効化」ボタンをクリックします。

### 切り替えフロー

1. 「有効化」ボタンをクリック
2. CC Switch が Windows 資格情報マネージャからそのプロバイダーの鍵を読み出し、ユーザーレベルの環境変数へ書き込んで、live 設定ファイルを書き換える
3. カードのステータスが「現在有効」に変更
4. **すでに開いているターミナルは開き直しが必要**です。新しい変数が読み込まれるのはそこから以降です

> ⚠️ そのプロバイダーにまだ鍵が保存されていない場合（例：別デバイスから同期復元した直後）、切り替えは拒否され、先に API key を補完するよう案内されます。

**ターミナルを開き直したくない場合**：Claude タブではプロバイダーカードの「ターミナルを開く」をクリックしてください。CC Switch がそのプロバイダーの認証情報を起動するターミナルプロセスへ直接注入するため、開き直しなしで使えます。Codex と Pi は現状ターミナルの開き直しが必要です。

### ステータス表示

| ステータス | 表示 | 説明 |
|------|------|------|
| 現在有効 | 青い枠 + ラベル | 現在使用中のプロバイダー |
| 鍵が必要 | 通知バッジ | 鍵が存在しない（同期復元後など）。プロバイダーを編集して補完が必要 |
| 通常 | デフォルトのスタイル | 有効化されていないプロバイダー |

## トレイでの素早い切り替え

システムトレイから素早く切り替えられ、メイン画面を開く必要がありません。

### 操作手順

1. システムトレイの CC Switch アイコンを右クリック
2. 対応するアプリのサブメニュー（例：「Claude · 現在のプロバイダー」）にマウスを合わせる
3. 切り替えたいプロバイダー名をクリック
4. 切り替え完了、トレイに短い通知が表示

> ⚠️ トレイからの切り替えも同じ供給経路（ユーザーレベルの環境変数）をたどるため、**すでに開いているターミナルは同様に開き直しが必要です**。

### トレイメニュー構造

トレイメニューは **アプリ別の階層サブメニュー** となっており、各アプリに独立したサブメニューが用意されています：

| サブメニュー | 説明                                                                 |
| ------------ | -------------------------------------------------------------------- |
| Claude       | Claude のすべてのプロバイダー                                        |
| Codex        | Codex のすべてのプロバイダー                                         |
| Pi           | Pi のすべてのプロバイダー                                            |

**階層サブメニューの利点**：

- **メニューのオーバーフロー防止**：プロバイダーが多数ある場合、フラットなリストでは画面の高さを超えますが、階層サブメニューは本質的に無限に拡張できます
- **サブメニューのタイトルに現在有効なプロバイダーを表示**：サブメニューを開かなくても、Claude / Codex / Pi がどのプロバイダーを使用中か確認できます
- **アプリ別の分離**：Claude のプロバイダーを切り替えても Codex や Pi のビューには影響しません

> 💡 **ヒント**：バックグラウンド常駐 + 軽量モード + 階層サブメニューの組み合わせは、複数のアプリを頻繁に切り替えるヘビーユーザーに特に適しています。[1.5 個人設定 → 軽量モード](../1-getting-started/1.5-settings.md) を参照してください。

## 反映方法

3 つのアプリの認証情報はいずれも**ユーザーレベルの環境変数**経由で供給されるため、共通点は **新しく開いたターミナルで新しい値が反映される** という点です。

### Claude Code

- CC Switch は `ANTHROPIC_AUTH_TOKEN`（またはプロバイダーの認証フィールドに応じて `ANTHROPIC_API_KEY`）と `ANTHROPIC_BASE_URL` を `HKCU\Environment` に書き込み、`WM_SETTINGCHANGE` をブロードキャストします
- `~/.claude/settings.json` にこれらのキーは含まれないため、環境変数を上書きすることはありません
- ターミナルを閉じて開き直せば反映されます

### Codex

- サードパーティプロバイダー：CC Switch は `CC_SWITCH_CODEX_API_KEY` 環境変数を書き込み、`~/.codex/config.toml` の対応する `[model_providers.<id>]` テーブルには `env_key = "CC_SWITCH_CODEX_API_KEY"` と `base_url` のみを記述します
- 公式 API key プロバイダー：`OPENAI_API_KEY` を書き込みます
- ターミナルを閉じて開き直せば反映されます

### Pi

- 有効化された各 Pi プロバイダーはそれぞれ専用の変数 `CC_SWITCH_PI_<KEY>_API_KEY` を持ち、`~/.pi/agent/models.json` には `apiKey: "$CC_SWITCH_PI_<KEY>_API_KEY"` と記述されます
- Pi は複数プロバイダーの同時有効化に対応しており、1 プロバイダーの有効化 / 削除はそのプロバイダー自身の変数だけを増減します
- Pi セッションを開き直せば変更が反映されます

## 設定ファイルの変更

プロバイダーを切り替える際、CC Switch は以下を変更します。

### Claude

| 位置 | 変更内容 |
|------|----------|
| `HKCU\Environment`（ユーザーレベル環境変数） | `ANTHROPIC_*` を書き込む。`HKLM` には一切書かない |
| `~/.claude/settings.json` | 除去後の設定（モデル名などの機密でない env）を書き込む。`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL` は**含まない** |

### Codex

| 位置 | 変更内容 |
|------|----------|
| `HKCU\Environment` | `CC_SWITCH_CODEX_API_KEY`（サードパーティ）または `OPENAI_API_KEY`（公式）を書き込む |
| `~/.codex/config.toml` | `env_key` の変数名と現在のプロバイダーの `base_url` を書き込む。`experimental_bearer_token` は含まない |

> 💡 CC Switch は `~/.codex/auth.json` を書かないため、`codex login` でご自身が構築したログイン状態は上書きされません。

### Pi

| 位置 | 変更内容 |
|------|----------|
| `HKCU\Environment` | `CC_SWITCH_PI_<KEY>_API_KEY`（および機密ヘッダの変数）を書き込む |
| `~/.pi/agent/models.json` | プロバイダーノードを書き込む。`apiKey` は `$変数名`、`baseUrl` は実際のアドレス |

> ℹ️ Codex と Pi の `base_url` は live ファイルに書く必要があります（対応 CLI がこのフィールドでの変数参照に対応していないため）。また現在有効な 1 件だけを記述し、他のプロバイダーの Base URL は引き続き資格情報マネージャのみにあります。

## 切り替え失敗時の対処

切り替えに失敗した場合、考えられる原因：

### 鍵の欠落

プロバイダーに API key が保存されたことがありません（新規作成時に入力しなかったか、別デバイスからの同期復元）。

**解決方法**：そのプロバイダーを編集し、鍵を再入力して保存してください。

### 環境変数の競合

ユーザーレベルの環境に、CC Switch が書き込んだものではない同名変数がすでに存在し、値も異なります。CC Switch はまず競合ダイアログを表示し、相手側の変数名末尾 4 桁のみ示します。

**解決方法**：「引き継ぐ（上書き）」を確認してから切り替えを実行し直すか、切り替えをキャンセルして自前で対処してください。引き継ぐと元の値は上書きされ保持されません。詳細は [5.4 環境変数の競合](../5-faq/5.4-env-conflict.md) を参照してください。

### 設定ファイルがロックされている

他のプログラムが設定ファイルを使用中です。

**解決方法**：実行中の CLI ツールを閉じてから、再度切り替えを試みてください。

### 権限不足

設定ファイルへの書き込み権限がありません。

**解決方法**：設定ディレクトリの権限設定を確認してください。

### 設定形式エラー

プロバイダー設定の JSON 形式に誤りがあります。

**解決方法**：プロバイダーを編集して、JSON 形式を確認・修正してください。

# 5.2 よくある質問 FAQ

## インストールに関する問題

### Windows でインストール後に起動できない

**考えられる原因**：
- WebView2 ランタイムが不足
- ウイルス対策ソフトによるブロック

**解決方法**：
1. [Microsoft Edge WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) をインストール
2. CC Switch をウイルス対策ソフトのホワイトリストに追加

### 「Windows 資格情報マネージャにアクセスできません」と表示される

CC Switch は鍵を Windows 資格情報マネージャに保存しており、取り出せない場合はそのまま失敗します。平文保存へフォールバックすることはありません。

**解決方法**：
1. Windows の「資格情報マネージャ」コントロールパネルが正常に開くことを確認
2. 関連するシステムサービスが実行中であることを確認
3. 企業ドメイン環境で認証情報がローミングプロファイルとともに同期する設定の制限がある場合は、ローカル永続化へ変更
4. 対処後にダイアログの「再試行」をクリック。このダイアログに「スキップ」はありません

## プロバイダーに関する問題

### プロバイダーを切り替えても反映されない

**原因**：CC Switch は**ユーザーレベルの環境変数**経由で認証情報を供給するため、実行中のターミナルプロセスは古い値を引き継いでいます。

**解決方法**：
- ターミナルを閉じて開き直す（Claude Code / Codex / Pi すべてに適用）
- または Claude タブでプロバイダーカードの「ターミナルを開く」をクリックすると、そのターミナルへ認証情報が直接注入されます
- 開き直しても反映されない場合は、`~/.claude/settings.local.json` またはプロジェクト単位の `.claude/settings.json` に `env.ANTHROPIC_*` がないか確認してください。これらはプロセスの環境変数を上書きします。詳細は [5.4 環境変数の競合](./5.4-env-conflict.md) を参照

### 切り替えが拒否され、鍵が必要と表示される

**原因**：そのプロバイダーに API key が保存されたことがないか、別デバイスから同期／インポートされたものです。

**解決方法**：そのプロバイダーを編集し、API key（とエンドポイントアドレス）を入力し直して保存してください。

> 💡 鍵はエクスポートにも同期にも含まれないため、デバイス後は必ず再入力が必要です。これは仕様で、バグではありません。

### 環境変数の競合と表示される

**原因**：ユーザーレベルの環境に、CC Switch が書き込んだものではない同名変数がすでに存在し、値も異なります。

**解決方法**：競合ダイアログで「引き継ぐ（上書き）」を選んでから切り替えを実行し直すか、切り替えをキャンセルして自前で対処してください。引き継ぐと元の値は上書きされ、保持されません。詳細は [5.4 環境変数の競合](./5.4-env-conflict.md) を参照してください。

### API Key が無効

**確認手順**：
1. API Key が正しくコピーされているか（余分なスペースがないか）
2. API Key が期限切れでないか
3. エンドポイントアドレスが正しいか
4. ターミナルを開き直し、CLI が新しい変数を読み込んでいるか

### 公式ログインに戻すには

**操作手順**：
1. 「公式ログイン」プリセット（Claude / Codex）を選択
2. 「有効化」をクリック
3. ターミナルを開き直す
4. CLI ツール自身のログインフローに従って操作（例：`codex login`）

> 💡 CC Switch は OAuth ログインを管理せず、`~/.codex/auth.json` にあるご自身のログイン状態も上書きしません。

## データに関する問題

### 設定が消えた

**考えられる原因**：
- 設定ディレクトリが削除された
- データベースが破損

**解決方法**：
1. `~/.cc-switch/` ディレクトリが存在するか確認
2. バックアップから復元：`~/.cc-switch/backups/`
3. または以前にエクスポートした設定ファイルからインポート

> ⚠️ データベースを失っても資格情報マネージャ内の鍵には影響しませんが、プロバイダーは再作成して鍵を補完し直す必要があります。「資格情報マネージャ」コントロールパネルで `cc-switch/` プレフィックスのエントリを手動で照合することもできます。

### 設定のインポートに失敗する

**考えられる原因**：
- ファイル形式のエラー
- バージョンの非互換性

**解決方法**：
1. ファイルが CC Switch からエクスポートされた SQL バックアップファイルであることを確認
2. ファイル内容が完全であるか確認
3. テキストエディタで開いてフォーマットを確認

### エクスポートが拒否され、鍵らしき値が検出されたと表示される

エクスポート前に CC Switch は回帰ガードとしてテキストを走査します。ヒットした場合は、異常なデータがデータベースに混入していることを意味します。

**解決方法**：疑わしいプロバイダーを削除して再試行してください。旧バージョンのインポートで持ち込まれた平文の鍵である場合は、インポート処理が資格情報マネージャへ抽出するため、アプリを開き直してから再度エクスポートすれば対処できます。

## その他の問題

### トレイアイコンが表示されない

**Windows**：
- タスクバーの設定で、CC Switch のアイコンが非表示になっていないか確認
- 「設定 → 一般 → ウィンドウ動作」でトレイアイコンの表示が有効か確認

### インターフェースの表示が異常

**解決方法**：
1. テーマを切り替えてみる（ライト/ダーク）
2. アプリを再起動
3. `~/.cc-switch/settings.json` を削除して設定をリセット

### 新しいバージョンへアップグレードするには

CC Switch にはアプリ内の更新機能がありません。起動時に新しいバージョンを確認することも、ダウンロードを促すこともありません。

**アップグレード方法**：[GitHub Releases](https://github.com/farion1231/cc-switch/releases) から最新の Windows インストーラ（MSI）またはポータブル版（ZIP）をダウンロードして上書きインストールします。設定と認証情報は影響を受けません。

## 軽量モード

### 軽量モードに入るには？

システムトレイメニューから「軽量モード」をトグルします。メインウィンドウが閉じ、CC Switch はトレイ専用アプリとして動作します。再度トグルするか「メインウィンドウを開く」をクリックすると終了します。

### 軽量モードではメモリ使用量が少なくなる？

はい。軽量モードではメインウィンドウとその Web ビューを破棄するため、トレイメニュー機能を維持しながらメモリ使用量を大幅に削減します。

## ヘルプの入手

### Issue の提出

上記の方法で問題が解決しない場合：

1. [GitHub Issues](https://github.com/farion1231/cc-switch/issues) にアクセス
2. 類似の問題がないか検索
3. なければ新しい Issue を作成
4. 以下の情報を提供：
   - Windows のバージョン
   - CC Switch のバージョン
   - 問題の説明と再現手順
   - エラーメッセージ（ある場合）

### ログファイル

CC Switch のログはアプリケーション設定ディレクトリに保存されます。既定ではホームディレクトリ内の `.cc-switch` です。詳細設定で設定ディレクトリを変更した場合は、その場所を基準にしてください。

Issue を提出する際は、問題に応じて次のファイルを添付してください：

- 一般的なエラーとネットワークの問題：`~/.cc-switch/logs/cc-switch.log` とローテーション済みファイル
- アプリケーションのクラッシュ：`~/.cc-switch/crash.log`、`crash.log.1`、`crash.log.2`
- Windows の既定パス：`C:\Users\<ユーザー名>\.cc-switch\...`

実行ログは 20 MB ごとにローテーションされ、直近 4 個のアーカイブを保持します。アプリを再起動しても既存ログは削除されません。ログには鍵の値は書き込まれませんが実行環境の情報が含まれる可能性があるため、公開前に内容を確認することを推奨します。

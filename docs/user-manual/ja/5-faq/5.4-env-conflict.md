# 5.4 環境変数の競合

## 機能説明

CC Switch は**ユーザーレベルの環境変数**（レジストリ `HKCU\Environment`）経由で CLI に認証情報を供給します。供給が環境変数に依存する以上、自分で他所に設定した同名変数と競合する可能性があるため、CC Switch はそれらを検出・報告します。

**検出する変数のプレフィックス**：

| アプリ | マッチするプレフィックス |
|------|----------|
| Claude | `ANTHROPIC*`（例：`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL`） |
| Codex | `OPENAI*`（例：`OPENAI_API_KEY`） |

CC Switch は内部で**どの変数を自分が書いたか**も記録しています（データベース `settings` テーブルの `managed_env_vars`）。自分が書いた変数を再度上書きする場合は競合として扱われません。

## 2 種類の競合シナリオ

### 切り替え時のブロック型競合

プロバイダーを切り替える際、書き込もうとする変数がすでに存在し、CC Switch が書いたものではなく、かつ値が異なる場合 —— CC Switch は**書き込まず**、競合ダイアログを表示します。

| フィールド | 説明 |
|------|------|
| 変数名 | 環境変数名 |
| 現在の値 | **末尾 4 文字のみ**表示（`***wxyz` の形式）。完全な値が画面へ返されることは一切ありません |
| 帰属 | `foreign`（他所の変数） |

選択できる操作：

- **引き継ぐ（上書き）**：CC Switch が新しい値で上書きし、この変数を自分の管理下として登録。その後そのまま切り替えを完了します
- **切り替えをキャンセル**：何も変更せず元の状態を維持します

> ⚠️ **重要**：引き継ぐと元の値は上書きされ**保持されません**——CC Switch は上書きした変数値のバックアップを取らなくなりました。引き継ぐ前に、その古い値が必要ないことを確認してください。

### 常時表示の警告バナー

メイン画面の上部に、検出された同名変数を並べた黄色い警告バナーが表示されることがあります。レジストリ由来に加え、**読み取り専用**の警告も一種含まれます：

| ソース | 説明 | CC Switch で削除できるか |
|------|------|----------------------|
| ユーザーレジストリ（`HKEY_CURRENT_USER\Environment`） | Windows のユーザーレベル環境変数 | ✅ 可能 |
| システムレジストリ（`HKEY_LOCAL_MACHINE\...\Environment`） | Windows のシステムレベル環境変数 | ❌ 報告のみ（読み取り専用） |
| `~/.claude/settings.local.json` | Claude 自身のローカル上書きファイル内の `env.ANTHROPIC_*` | ❌ 報告のみ（読み取り専用） |

> 💡 ユーザーレベルの変数は同名のシステムレベル変数を上書きします（`PATH` を除く）。そのためシステムレベルの同名変数は、通常は CC Switch を使わない場面にのみ影響します。

## 競合の処理

### 処理する変数を選択

1. 処理する変数にチェックを入れる（読み取り専用のソースは選択できません）
2. または「すべて選択」をクリック

### 変数を削除

1. 「選択を削除」ボタンをクリック
2. 削除操作を確認
3. CC Switch は `HKCU\Environment` からその変数を削除し、本プロセスの環境も同期更新したうえで、`WM_SETTINGCHANGE` をブロードキャストします

> ⚠️ **自動バックアップは廃止されました**：旧バージョンでは削除前に変数値を平文でファイルへバックアップしていましたが、この仕組みは削除されました（平文バックアップ自体が修正対象でした）。削除前に、元の値が必要ないことをご自身で確認してください。

## 警告を無視する

競合が使用に影響しないと確認できる場合：

1. 警告バナー右側の「閉じる」ボタンをクリック
2. 警告が一時的に非表示になる
3. 次回の起動時に再度検出が行われる

## 手動での処理

CC Switch 経由で対処したくない場合は、手動で処理できます：

### Windows のユーザーレベル変数

1. 「システムのプロパティ → 詳細設定 → 環境変数」を開くか、PowerShell を使用
2. **ユーザー変数**から競合している変数を見つける
3. その変数を削除または変更

### システムレベル変数

管理者権限が必要です。CC Switch は `HKLM` に一切触れません。「環境変数」ダイアログのシステム変数欄でご自身で対処してください。

### Claude のローカル上書きファイル

`~/.claude/settings.local.json` とプロジェクト単位の `.claude/settings.json` にある `env.ANTHROPIC_*` は、プロセスの環境変数より優先されるため、CC Switch が供給した値を覆してしまいます。CC Switch はこれらのファイルを変更しないので、該当エントリを自分で削除またはコメントアウトしてください。

## なぜ競合が発生するのか

環境変数の値は CLI がプロセス起動時に読み取るため、以下の問題が起こり得ます：

- CC Switch が設定したプロバイダー設定が他所の変数値に上書きされる
- API リクエストが間違ったエンドポイントに送信される
- 間違った API キーが使用される

## ベストプラクティス

1. **これらの変数は CC Switch に独占させる**：システム環境変数や shell 設定で `ANTHROPIC_*` / `OPENAI_API_KEY` を別途設定しない
2. **定期的に確認**：競合の警告に注意し、速やかに対処
3. **引き継ぐ前に古い値を確認**：上書きされた元の値は CC Switch では保管されません
4. **変更後はターミナルを開き直す**：CC Switch は `WM_SETTINGCHANGE` をブロードキャストしますが、新しい値を読み取れるのは新しく起動するプロセスだけです

## 引き継ぎを取り消す

本当に残しておきたかった変数を引き継いでしまった場合：

1. 別プロバイダーへ切り替えるか、そのプロバイダーを削除する —— CC Switch は自分が登録した変数を削除します
2. 「設定 → 詳細 → 資格情報マネージャのメンテナンス」で、残った可能性のある認証情報エントリを整理する
3. 元の値は自分で復元する必要があります（自分自身のバックアップから、またはプロバイダーのコントロールパネルで再取得するなど）

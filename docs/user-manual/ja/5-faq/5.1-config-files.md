# 5.1 設定ファイルの説明

## CC Switch のデータストレージ

### ストレージディレクトリ

デフォルトの場所：`~/.cc-switch/`（Windows では `%USERPROFILE%\.cc-switch\`）

設定で場所をカスタマイズ可能です（クラウド同期用）。

### ディレクトリ構造

```
~/.cc-switch/
├── cc-switch.db      # SQLite データベース（SSOT、鍵を一切含まない）
├── settings.json     # デバイスレベルの設定（鍵を一切含まない）
├── logs/             # 実行ログ（マスキング済み）
├── crash.log         # クラッシュ記録
├── skills/           # スキル SSOT ディレクトリ
├── skill-backups/    # スキルバックアップ（アンインストール時に作成）
└── backups/          # データベースバックアップ
```

### 認証情報はどこにあるか

**これらのファイルの中にはありません。** API key、エンドポイントアドレス、および機密と判定された環境変数の永続化先は **Windows 資格情報マネージャ**（Credential Manager）のみで、エントリ名は `cc-switch/` プレフィックスを持ちます。データベース、`settings.json`、エクスポートファイル、同期ペイロード、ログのいずれにも鍵の値は残しません。

### データベースの内容

`cc-switch.db` は SQLite データベースで、以下を保存しています：

| テーブル | 内容 |
|-----|------|
| providers | プロバイダー設定（鍵とエンドポイントアドレスを除去済み） |
| mcp_servers | MCP サーバー設定 |
| prompts | プロンプトプリセット |
| skills | スキルのインストール状態 |
| skill_repos | スキルリポジトリ設定 |
| profiles | 設定スナップショット |
| settings | アプリ設定と環境変数の所有権記録 |

### デバイス設定

`settings.json` はデバイスレベルの設定を保存します：

```json
{
  "language": "zh",
  "theme": "system",
  "minimizeToTrayOnClose": true,
  "launchOnStartup": false,
  "visibleApps": { "claude": true, "codex": true, "pi": true },
  "claudeConfigDir": null,
  "codexConfigDir": null,
  "piConfigDir": null,
  "skillSyncMethod": "auto",
  "skillStorageLocation": "cc_switch",
  "backupIntervalHours": 24,
  "backupRetainCount": 10,
  "preferredTerminal": "wt"
}
```

これらの設定はデバイス間で同期されません。WebDAV のパスワードや S3 の Access Key もここにはなく、Windows 資格情報マネージャ側にあります。

### 自動バックアップ

`backups/` ディレクトリに自動バックアップが保存されます：

- スケジュールに従い作成（間隔と保持数は設定可能）
- デフォルトで直近 10 件を保持
- ファイル名にタイムスタンプを含む
- バックアップは現在鍵を含まないため、安全に保存・共有できます

アップグレード時にはさらに `pre-secrets-migration-*.db`（移行前の v18 データベースで平文の鍵を含む）が 1 件生成されます。ロールバック専用で、自動的に削除されることはありません。

## 環境変数による供給

CC Switch は**ユーザーレベル**の環境変数（レジストリ `HKCU\Environment`）のみを書き、`HKLM` には一切書きません。一括書き込み後に `WM_SETTINGCHANGE` をブロードキャストします。

| 用途 | 変数名 |
|------|--------|
| Claude API Key | `ANTHROPIC_AUTH_TOKEN` または `ANTHROPIC_API_KEY` |
| Claude エンドポイント | `ANTHROPIC_BASE_URL` |
| Codex サードパーティ API Key | `CC_SWITCH_CODEX_API_KEY` |
| Codex 公式 API Key | `OPENAI_API_KEY` |
| Pi API Key | `CC_SWITCH_PI_<KEY>_API_KEY` |
| Pi 機密ヘッダ | `CC_SWITCH_PI_<KEY>_HEADER_<NAME>` |

どの変数を CC Switch 自身が書いたのかは、データベースの `settings` テーブルの `managed_env_vars` キーに記録されます。

## Claude Code の設定

### 設定ディレクトリ

デフォルト：`~/.claude/`

### 主要ファイル

```
~/.claude/
├── settings.json     # メイン設定ファイル
├── CLAUDE.md         # システムプロンプト
└── skills/           # スキルディレクトリ
    └── ...
```

### settings.json

```json
{
  "env": {
    "ANTHROPIC_MODEL": "kimi-k2.7-code",
    "CLAUDE_CODE_MAX_CONTEXT_TOKENS": "262144"
  }
}
```

> ⚠️ **注意**：CC Switch はこのファイルへ `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL` を**書き込みません**。Claude Code はこれらをプロセス環境から直接読み取るため、値は環境変数経由で供給されます。書き込み前にもう一段ガードがあり、機密キーが検出されると書き込みを拒否します。

`~/.claude/settings.local.json` やプロジェクト単位の `.claude/settings.json` にご自身で `env.ANTHROPIC_*` を書いている場合は、**それらがプロセスの環境変数を上書きします**。CC Switch はこれらのファイルを変更せず、読み取り専用の競合警告のみを表示します。

### MCP 設定

MCP サーバーの設定は `~/.claude.json` にあります：

```json
{
  "mcpServers": {
    "mcp-fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
```

## Codex の設定

### 設定ディレクトリ

デフォルト：`~/.codex/`

### 主要ファイル

```
~/.codex/
├── auth.json         # ご自身の Codex ログイン状態（CC Switch は書かない）
├── config.toml       # メイン設定 + MCP
├── AGENTS.md         # システムプロンプト
├── skills/           # スキルディレクトリ
└── sessions/         # セッション記録
```

### config.toml

```toml
model_provider = "custom"
model = "gpt-5.2"

[model_providers.custom]
name = "custom"
base_url = "https://api.example.com/v1"
wire_api = "responses"
env_key = "CC_SWITCH_CODEX_API_KEY"
```

| フィールド | 説明 |
|------|------|
| `env_key` | ユーザーレベルの環境変数名を指す文字列で、鍵の値はファイル内にない |
| `base_url` | エンドポイントアドレス。**例外**：Codex CLI はこのフィールドでの変数参照に対応していないため、現在有効なプロバイダーの Base URL がここに書かれます。他のプロバイダーの Base URL は引き続き Windows 資格情報マネージャにのみ保存されます |

> ⚠️ CC Switch は `~/.codex/auth.json` を書かず、`config.toml` へ `experimental_bearer_token` を書き込むこともありません。

## Pi の設定

### 設定ディレクトリ

デフォルト：`~/.pi/agent/`

### 主要ファイル

```
~/.pi/agent/
├── models.json       # プロバイダーとモデルの設定
├── AGENTS.md         # システムプロンプト
├── skills/           # スキルディレクトリ
└── sessions/         # セッション記録
```

### models.json

```json
{
  "providers": {
    "example": {
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "$CC_SWITCH_PI_EXAMPLE_API_KEY"
    }
  }
}
```

`apiKey` は必ず `$変数名` の形になります。`baseUrl` は Codex と同じく例外で、Pi CLI はこのフィールドでの変数参照に対応していないため、有効化中のプロバイダーはアドレスが平文で書かれます。

## 設定の優先順位

CC Switch が設定を変更する際の優先順位：

1. **Windows 資格情報マネージャ** - 鍵とエンドポイントアドレスの唯一の真実源
2. **CC Switch データベース** - その他の設定の単一事実源 (SSOT)
3. **Live 設定ファイル / ユーザーレベル環境変数** - プロバイダー切り替え時に書き込み
4. **バックフィル機能** - 現在有効なプロバイダーの編集時に Live ファイルから読み取り（除去済みの部分のみバックフィル）

## 手動での設定編集

### 手動編集可能なもの

- CLI ツールの設定ファイル（機密でない部分は CC Switch がバックフィルします）
- CC Switch の `settings.json`

### 手動編集を推奨しないもの

- `cc-switch.db` データベースファイル
- バックアップファイル

### 編集後の同期

CLI ツールの設定を手動で編集した場合：

1. CC Switch を開く
2. 対応するプロバイダーを編集
3. 手動変更の内容がバックフィルされていることを確認
4. 保存してデータベースに同期

> ⚠️ live ファイルに平文の鍵を手書きした場合、CC Switch は読み取り／同期の過程でそれを資格情報マネージャへ抽出し、ファイル内の値を変数参照へ置き換えます。

## 設定の移行

### 旧バージョンからの移行

現在のバージョン（データベーススキーマ v19）へアップグレードすると、初回起動時に以下が自動完了します：

1. `pre-secrets-migration-*.db` ロールバック用バックアップを生成
2. 削除されたアプリのプロバイダー / MCP / skills の行、およびローカルルーティング関連テーブルを削除
3. すべてのプロバイダーの鍵とエンドポイントアドレスを Windows 資格情報マネージャへ移行し、データベースから除去
4. WebDAV のパスワード、S3 の Access Key を資格情報マネージャへ移行
5. 旧バージョンの平文の残骸をクリーンアップ：`config.json` とその `.bak` / `.migrated`、`codex_oauth_auth.json`、`backups/env-backup-*.json`、`%TEMP%\claude_*.json`
6. live ファイルを書き換え、環境変数を供給
7. 移行結果を説明する一回限りのダイアログを表示

移行は冪等であり、中断しても次回起動時に再実行されます。資格情報マネージャが利用できない場合は処理を停止してエラーを表示し、平文での書き戻しには決してフォールバックしません。

### デバイス間の移行

1. 移行元のデバイスで設定をエクスポート
2. 移行先のデバイスで設定をインポート
3. またはクラウド同期機能を使用

> ⚠️ エクスポートも同期も**鍵を持ちません**。移行先のデバイスではすべてのプロバイダーが「鍵が必要」と表示され、API key を個別に補完してから切り替えられます。

## 設定のバックアップに関するアドバイス

### 定期的なバックアップ

定期的に設定をエクスポートすることを推奨します：

1. 設定 → 詳細 → データ管理
2. 「エクスポート」をクリック
3. 安全な場所に保存

### バックアップに含まれる内容

エクスポートファイルには以下が含まれます：

- すべてのプロバイダー設定（鍵を含まない）
- MCP サーバー設定
- Prompts プリセット
- アプリ設定

### 含まれない内容

- すべての鍵とエンドポイントアドレス（Windows 資格情報マネージャ側にあります）
- デバイスレベルの設定（デバイス間の移動に適さないため）

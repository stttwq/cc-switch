# 方案：以 1Password 作为密钥后端

状态：设计待确认（未开始实现）
适用版本：拟定 2.3.0
作者：与用户共同定稿

---

## 1. 目标与动机

把 CCS 的密钥存储从 **Windows 凭据管理器** 迁移到 **1Password**，达成：

1. 摆脱对凭据管理器的依赖（凭据管理器对同用户进程零门槛可读）
2. 密钥全程存在 1Password，本地**不存密钥**（连密文都不存），只存"这把钥匙在 1Password 的哪个格子"的引用
3. 用到时现场向 1Password 取，用完即弃，**不缓存进内存**
4. 只有 1Password 解锁时 CCS 才能取到钥匙；锁定 / 未装 op / 断网时取不到

使用前提（用户已确认接受）：

- 每个供应商用很久、不频繁切换，所以"每次取钥匙约 6 秒"可接受
- 断网或连不上 1Password 服务器时 CCS 用不了（即使已解锁）
- 解锁走 Windows Hello 通道（PIN / 生物均可），已实测跑通

## 2. 安全模型（诚实边界）

### 能防住

- 别人拷走你的硬盘 / DB 文件：里面没有密钥，拿不到
- CCS 没运行 / 1Password 锁定时：钥匙在 1Password 加密保险箱里，读不出
- 读 CCS 内存：全程不缓存，CCS 内存里几乎没有钥匙

### 防不住（所有密码方案共同的天花板）

- 钥匙最终必须交给 claude / codex / pi 使用：
  - 右键打开终端：钥匙以**环境变量**注入目标终端进程，终端存活期间钥匙在其环境中
  - 部分工具（如 Codex `auth.json`）要求钥匙**明文写入其配置文件**（落盘），这是工具要求，非 CCS 可控
- 同用户的恶意进程可以读目标终端的环境 / 目标工具的配置或内存 —— 它不需要碰 CCS

### 净效果

从"凭据管理器：随时零门槛可读"降到"只有正在使用某供应商时、且需针对特定终端/工具下手"。是实质提升，非绝对防护。

## 3. 架构总览

### 当前

```
DB(providers.settings_config, 剥离密钥)  +  Windows 凭据管理器(api_key / base_url)
         └── 切换/右键 → 从凭据管理器读 → 注入终端环境变量 / 写 live 配置
```

### 目标

```
DB(providers.settings_config, 剥离密钥)  +  DB 存 1Password 引用(op://vault/item)
         └── 切换/右键 → 调 op 现场取 → 注入终端环境变量 / 写 live 配置 → 立即弃
1Password(保险箱, 加密, Windows Hello 解锁)  ←── 密钥真源
```

关键简化：全程取用、不缓存，所以

- **右键独立进程直接调 op 取钥匙即可**，不需要常驻 GUI、不需要进程间通信（IPC）、不需要内存 KEK
- **不需要自己做数据库加密、不需要主口令**（1Password 全包）

---

## 4. 密钥在 1Password 里怎么组织

- 每个供应商一个 1Password 条目（category：Password 或 API Credential）
- 一个条目内放该供应商需要的字段：`api_key`、`base_url`（一次 `op item get` 取回，避免一个操作取两次）
- CCS 的 DB 里，为每个供应商存一个**引用**，形如 `op://<vault>/<item-id>`（用 item UUID 而非标题，避免改名失效）
- 待定：用现有 `Personal` 保险箱，还是新建专用 `CCS` 保险箱（推荐专用，便于隔离与授权管理）

命名建议（待确认）：`CCS · {claude|codex|pi} · {供应商显示名}`

---

## 5. 读取路径改造

统一收口在现有单一真源函数 `provider_env_pairs`（切换与右键共用），把"从凭据管理器 get"换成"调 op 取"。

- 新增 `secrets` 后端抽象的一个实现：`OnePasswordSecretStore`
  - `op` 可执行文件发现：PATH → winget 安装路径 → 用户自定义路径（存 settings）
  - 取值：`op item get <item-id> --vault <vault> --format json`，解析出字段
  - 明文用 `Zeroizing`，注入终端后立即清零
  - 失败分类：op 未找到 / 1Password 锁定 / 网络不可达 / 条目不存在 → 各自清晰报错
- GUI 端：切换供应商、"运行 X" 均走同一路径
- CLI 端（`ccs.exe` / `ccs-open.exe`）：`build_state()` 里把密钥后端换成 1Password 实现；右键每次调 op（约 6 秒），符合"全程取用"

---

## 6. 老数据搬家（一次性迁移）

本机当前凭据管理器里有 21 条 `cc-switch/*`（各供应商 api_key + base_url，及 app 级 webdav/sync 口令）。

迁移流程（GUI 里一个"迁移到 1Password"按钮，带进度与确认）：

1. 枚举凭据管理器所有 `cc-switch/v1/provider/*`
2. 按供应商聚合成条目，写入 1Password（每写一条约 6 秒，21 条约 2 分钟，一次性）
3. 把返回的 item 引用写回 DB
4. 校验：逐条 `op item get` 读回比对
5. 全部成功后，**可选**删除凭据管理器里的对应条目（默认保留做备份，用户手动确认后再删）

app 级口令（WebDAV 密码、S3、同步口令）是否也迁进 1Password：待确认（见决策点）。

---

## 7. 1Password 不可用时的降级

- op 未安装 / 未开集成 → 启动时检测，提示用户去装/开，CCS 进入"密钥不可用"只读态
- 1Password 锁定 → 取钥匙时触发 Windows Hello；用户不解锁则该操作失败并提示
- 网络不可达 → op 取值超时，明确报"连不上 1Password，请检查网络"
- 全程不静默失败、不回退到明文

---

## 8. 对已做/在计划工作的影响

- **2a 凭据便携包（已发布）**：迁移到 1Password 后功能重叠（1Password 自带加密同步）。建议：保留为"未用 1Password 的迁移/备份工具"，不删除；文档标注其定位。
- **2b WebDAV 同步密钥（计划中）**：**取消**。1Password 本身就是跨设备加密同步，换机装 CCS + 登录同一 1Password 即恢复，无需再做网盘同步密钥。
- **卸载清理**：仍保留清理凭据管理器残留（迁移后可能仍有备份条目）；1Password 里的条目不由卸载清理触碰（那是用户资产）。

## 9. 分阶段实施

1. **阶段 A：op 集成内核**
   - op 可执行发现 + `OnePasswordSecretStore` 读取实现 + 失败分类 + 单测（mock op）
   - 验证：GUI 切换、右键打开终端能从 1Password 取到并投递
2. **阶段 B：数据模型与引用**
   - DB 增加"1Password 引用"存储；provider 读取路径切换到 1Password 后端
   - 验证：切换/右键全链路
3. **阶段 C：迁移工具**
   - "迁移到 1Password"按钮：凭据管理器 → 1Password，回写引用，校验，可选清理
   - 验证：本机 21 条端到端搬家 + 读回比对
4. **阶段 D：降级与提示 + 文档**
   - 各失败态提示；设置页 op 路径配置；用户手册更新
   - 取消 2b；2a 定位说明
5. **阶段 E：打包与端到端验证**

预计工作量：约 2~4 天（不含反复联调网络导致的等待）。

---

## 10. 已知限制与风险

- 每次取钥匙在当前网络约 6~9 秒（网络问题，非软件；换网络可能变快）
- 钥匙在"交给工具用"时不可避免暴露（见 §2）
- 强依赖 op CLI + 1Password 桌面集成 + Windows Hello；任一缺失即不可用
- op 的按调用程序授权较弱：1Password 解锁且集成开启时，同用户其他进程也能调 op 读同一保险箱（与内存暴露同级的天花板）
